# Grafía · captura

The capture app: I'm reading a physical book, I meet a word I don't know, I look it up, it's saved, I review it later. iOS first, built with Expo (SDK 58, React Native 0.88, TypeScript). Offline-first, no accounts. The only network use is the word of the day (`../grafia-corpus/docs/BACKEND.md`).

## Read first

The specs live in the sibling repo, `../grafia-corpus`, which also builds the dictionary this app ships:

- `../grafia-corpus/docs/CAPTURA.md`: what v1 is and why. Spanish. §3 (capturing costs zero decisions) overrides every feature idea.
- `../grafia-corpus/docs/CLAUDE.md`: the dictionary's constraints, and the code standards both repos share.
- `../grafia-corpus/tests/forms.txt`: the lookup spec. Its header is the source of truth for lookup behavior.

## Non-negotiable constraints

- **Offline-first.** Everything works with no network. The network only brings the word of the day, and whatever arrives is cached and shape-checked (`parseDaily`) before use. No accounts, no sync in v1.
- **Nothing the user sees is in English.** Part-of-speech codes, relation codes and source glosses are English in the data; the app maps them to Spanish (`posLabel` in `src/lookup.ts`), and never shows English text.
- **The dictionary is read-only and read in place** from the app bundle (`openDictionary` in `src/db.ts`). Never copy it to the documents folder: that stores 60+ MB twice.
- **Captures live in `captures.db`, apart from the dictionary**, so a new dictionary never touches them. They are keyed on what was typed, saved with its accents (`canonical`); the lemma and sense are optional and resolved when read.
- **`src/lookup.ts` mirrors `grafia/dictionary.py` in the corpus repo**: `keysFor`/`keys_for`, `suggest`, `stripAccents`/`strip_accents`, the rare-reading cutoff and the score scale. Change one, change the other. `test/forms.test.mjs` runs `forms.txt` against the same `dictionary.db`, so both answer to one spec.
- **ñ and ü are letters, not accents.** Any accent-stripping in this repo must keep them (`stripAccents`, `plain` in `src/game.ts`).
- **The captures schema changes only by appending to `MIGRATIONS`** in `src/db.ts`, never by editing a shipped entry: phones that ran it never see the edit.
- **The content URL lives twice**: `CONTENT_URL` in `src/daily.ts` and `contentBase` in `targets/widget/DailyWordWidget.swift`. Change both.
- **Games never touch the review schedule.** Review answers go to `review_log`, game answers to `play_log`.

## Layout

- `App.tsx`: the shell. Tabs, the `grafia://buscar` link, database opening.
- `src/lookup.ts`: dictionary queries, with no imports so Node tests run the exact file. `src/review.ts` (Leitner scheduling) and `src/game.ts` (game logic) follow the same rule.
- `src/db.ts`: both databases, the captures migrations, every captures query.
- `src/daily.ts`: the word of the day's file contract, the Mexico City date, the shape check. No imports, like `lookup.ts`.
- `src/Entries.tsx`, `src/theme.ts`, `src/screens/`: the UI.
- `targets/widget/`: the search widget, the word-of-the-day widget (`DailyWordWidget.swift`, which fetches its own file and caches it) and the Control Center control, in Swift, added by `@bacons/apple-targets`. Intents that open the app go in `targets/widget/_shared/` so they are compiled into the app too; in the widget alone they cannot open it.
- `assets/dictionary.db`: built by `../grafia-corpus` and copied in with `npm run dictionary`. A build artifact, gitignored.
- `ios/`: generated by `npx expo prebuild`. Never edit it by hand; configure through `app.json` and config plugins.

## Working here

- Expo changes its APIs every SDK release. Check the versioned docs (`https://docs.expo.dev/versions/v58.0.0/`) or the installed type definitions instead of trusting memory.
- Add packages with `npx expo install`, not `npm install`, so versions match the SDK. Ask before adding a dependency.
- `npm test` runs the Node tests (`test/*.test.mjs`); `npm run typecheck` runs `tsc`. Both must pass before work is done.
- Installing on the iPhone (free Personal Team, expires every 7 days): build with `xcodebuild … -allowProvisioningUpdates` from `ios/`, then `xcrun devicectl device install app`. `npx expo run:ios --device` alone fails to sign. Sign only with the Personal Team set in `app.json` (`ios.appleTeamId`), never with any other team on the Mac.

## Code standards

Shared with `../grafia-corpus/docs/CLAUDE.md`:

- Comments are a last resort. Code should be self-documenting: clear names, small functions, obvious control flow. If a comment explains *what* the code does, delete the comment and fix the code.
- The exception is non-obvious domain knowledge: a measured finding, a platform quirk, a Spanish-morphology rule. Keep those to one or two lines.
- Code, identifiers and comments in English. Text the user sees in Spanish.
- **Never commit** unless explicitly asked. Show the diff; the owner decides what lands.
- Do not refactor code you were not asked to touch.

## Known gaps

The MVP was built fast. Before relying on it, these are open:

- Export exists but import does not, so there is no way to restore captures on a new phone.
- If the dictionary fails to open, the app stays on its loading screen with no error.
- Only pure logic is tested. There are no tests for `db.ts`, the screens, or end-to-end flows.
